# Opskeep Deliver Work — Sole Trader Note

Use when the requester is a solo tradesperson or solo freelancer working alone or with at
most a helper, not a team with handoffs between roles. See
[`docs/sole-trader-profile.md`](../../../docs/sole-trader-profile.md) for the full profile.

## What's different from the default profile

- Delivery is typically a single visit or a short, contiguous on-site run (a day, a few
  days), not a multi-week engagement with a status cadence. "Status" often means "did the
  job happen, is it done," not a weekly report.
- Handoffs and dependencies rarely apply solo. Don't manufacture a handoff step or an
  owner-to-owner dependency when there's only one owner.
- Blockers are more likely physical/logistical than coordination-based: parts on backorder,
  weather, access to the site, a permit not yet issued. Track them the same way (blocker,
  owner, next action) but don't force a team-delivery framing onto them.
- QA is usually a walkthrough with the client at job completion, not a formal review
  cycle.

## Output adjustment

Keep delivery status to what a single job needs:

- Job status: not started / in progress / done / needs follow-up.
- Any blocker (parts, weather, access, permit) with the next concrete action.
- Scheduled date/window if it moved.
- Client walkthrough/acceptance note, once done.

Skip the handoff and dependency-tracking sections of the default output shape unless a
second person (a helper, a subcontractor) is genuinely involved in this job.
